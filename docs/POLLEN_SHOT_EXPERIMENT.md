# Pollen shot experiment — current overshooter

Purpose: compare repeatable higher-angle / lower-speed shots before the hardware change. Separate misses and rim hits from clean entry followed by bounce-out. This is an independent **Pollen Shot Experiment** OpMode, group **testing**, not a replacement for match TeleOp. No drive constants, servo directions/endpoints, shot interpolation tables, shared physics profile, or Claude's turret diagnostics were changed. No robot deployment was performed.

## Three checks before implementation

1. **Trajectory and units:** independently evaluated the vacuum equation against numerical integration. At 6 ft release-to-mouth-center, the CAD 39.4° pose needs 9.88 m/s; 50° needs 6.47; 54° needs 6.08. Ideal single-wheel/stationary-hood translation is half wheel surface speed, not full surface speed. RPM and SDK ticks/s must be converted with the actual encoder counts per wheel revolution. 28 counts/rev is a motor assumption requiring verification, not the turret's 8192-count encoder. Feedforward uses volts/RPM, converted to motor duty with actual battery voltage. The existing baseline gains appear too small to reach these speeds when interpreted as volts, so this diagnostic uses a separate nominal motor feedforward plus bounded PI; it does not rescale or replace match gains.
2. **Opening and finite ball:** FIRST TU07 figures 9-10/11 show a pentagonal mouth, approximately 60° above horizontal for the frontal approach, not a horizontal hoop. A rising ball can enter. Ideal checks measure distance to all five rim edges, not only the center point. Frame thickness, internal surfaces, cell motion, rebound coefficients, and exact ball shape remain unmodeled. Lower launch speed at these candidate angles also lowers ideal entry speed, but does not guarantee retention or suppress spin-driven rebound.
3. **Real robot and errors:** current hood tables are all zero, no verified servo-position-to-launch-angle map exists, and 54° is an estimated linkage limit. Therefore no calculated angle is converted into a servo command automatically. Two mirrored hood servos use the existing HoodAngler directions. RPM readiness uses uncached signed hub velocity, not coarse per-loop position differences. Drive and turret motion, loop gaps, low/invalid voltage, target changes, and elapsed hood settling inhibit release. Expected shot RPM dip is allowed during a pulse; speed must recover before the next attempt. Hood settling is time-based, not measured position. Stationarity encoders do not prove absence of chassis slip or goal motion; the operator verifies aim and stability.

## Error envelope (not a measured probability)

Run `python3 tools/pollen_shot_envelope.py`. It checks 128 hypothetical uncertainty corners per candidate: ±2° exit-direction error, ±5% ball speed, ±5 cm range, ±0.5 in release height, ±2.5 cm lateral aim, Cd 0.3–0.6, Cl 0–0.2, plus 2 mm ball-radius and 5 mm rim allowance. Cd/Cl and errors are explicit assumptions, not BioBuzz measurements. The numerical flight is RK4; rim clearance uses the local tangent approximation, not a complete swept-sphere/body collision solver. It does not model retention, ball spin decay, side wind, or a moving cell.

None of the four tested 6/8-ft, 50/54° candidates clears every corner. Thus do not interpret a nominal 3700 RPM / 54° combination as a guaranteed shot or infer failure percentages from the corner counts. Exit-direction perturbations above 54° are hypothetical physical errors, not permitted servo requests. Use measurements to narrow the uncertainties. Initial uncertainty in wheel slip could exceed the ±5% assumed speed error.

## Setup and use today

1. Record the current shooter's baseline outcomes first. Position robot **stationary**, facing the upward cell; aim turret manually before starting. Measure horizontal distance from **ball release** to mouth center, not camera or drive center. Start at 6 ft. Keep the cell configuration consistent; record if it moves.
2. Verify flywheel encoder counts/revolution and positive RPM sign, feeder direction, blocker open/closed behavior, and an individual safe hood servo position. Measure actual ball launch angle from video. Use existing hood calibration/tuner for this verification; this OpMode intentionally does not invent a conversion or extend travel. Test the timed feed with ONE pollen initially: without a ball sensor, a pulse is NOT guaranteed to dispense exactly one ball. Adjust feed power/timing after observation. If gravity alone releases a ball when the blocker opens, OPENING can already launch it; speed/settling are checked before opening, but the attempt counter starts when the blocker is commanded open, not at a measured physical release time.
3. Select **Pollen Shot Experiment** and START. Dashboard config is this class. Set:
   - `HOOD_POSITION`: that individually verified existing servo position (default -1 blocks operation).
   - `MEASURED_LAUNCH_DEG`: measured exit elevation, between 31 and 54, for metadata/reference only.
   - `FLYWHEEL_TICKS_PER_REV`: verified wheel-revolution count; 28 is only the initial assumption for 1:1 bare motor.
   - `RELEASE_DISTANCE_FT`: measured release-to-mouth-center range.
   - `TARGET_RPM`: chosen experimental target, 500–5000 (default 0 blocks operation).
   - `FEED_POWER`: verified positive feeder power; default 0 blocks operation.
   - `HARDWARE_CONFIRMED=true` after the checks above.
4. With **RB released**, press **X** to apply a snapshot. This is when the hood moves; both mirrored servos receive the existing subsystem command. Configuration does not change mid-shot when Dashboard is edited. Apply only after labeling the previous attempt.
5. Hold **RB** to spin up and declare the robot is stationary and manually aimed. The code keeps drive motors and turret CR outputs at zero; it does not actively hold the turret or drive. It additionally checks drive encoder velocity ≤20 ticks/s and turret velocity ≤100 ticks/s. Verify these raw thresholds against your actual encoders/noise; they are not guaranteed physical pose tolerances. Hood waits ≥0.75 s, then measured RPM must remain within ±75 RPM with acceleration ≤400 RPM/s for 0.35 s. These are starting experiment tolerances, not validated match settings.
6. When **READY**, make a **fresh A press**. Early or held presses are not queued. Blocker opens for 0.15 s, then intake runs for a nominal 0.12 s, then blocker closes. A speed departure during OPENING cancels feed; label that attempt INVALID if no ball released. RPM dip during FEEDING is expected and does not truncate a normal pulse. Releasing RB or pressing **B**, motion, bad voltage/readings, or a >0.1 s loop gap closes the blocker and stops feed. Motor output stops on release/B or a motor fault. A stopped/late loop can only be noticed when execution resumes: the 0.12 s pulse can overshoot by up to a valid loop interval, or more if the loop actually stalls; this is not a hardware-timed one-ball indexer.
7. At least 0.8 s recovery plus continuous speed readiness is required before another attempt. Overspeed >5500 RPM, negative encoder speed below -150 RPM, invalid voltage, or failure to achieve stable speed within 5 seconds latches a motor fault; release RB to clear and inspect the cause. The experiment's nominal 6000-RPM-at-12-V feedforward, PI, 90% duty cap, and power slew limit are uncharacterized starting values, not a physical guarantee. Unreachable targets remain blocked; do not bypass readiness by widening thresholds arbitrarily.
8. After each completed/canceled blocker-open attempt, label with **D-pad UP = clean entry/stayed; DOWN = clean entry/exited; LEFT = miss; RIGHT = rim contact**. Label rim contacts as RIM even if they ultimately stay; this keeps the retention statistic limited to clean entries. No further attempt until the previous one is labeled. Verify actual ball passage on video: the count is commanded blocker-open attempts, not a sensor-confirmed ball count. If zero/multiple balls release, press **Y = INVALID/no ball**, preserve the footage, and correct feeding before continuing. INVALID attempts are excluded from outcome comparisons.
9. Release RB before adjusting. Compare 10 shots each at a verified ~50° and, if mechanically verified, ~54° setting. Illustrative aero calculation suggests around 3900/3700 RPM at 6 ft and around 3980/3890 RPM at 8 ft for assumed speed/surface ratio 0.45; these are search centers ONLY. Tune in small RPM steps from a known working shot, using entry observations. Repeat with several marked balls and compare both entry rate and retention after clean entry. Hold angle fixed while tuning RPM to avoid confusing causes. Do not automatically pick 54°: compare real outcomes and uncertainty.
10. STOP normally to save CSV under `/sdcard/FIRST/data/ShotExperiments/`. Retrieve with `adb pull /sdcard/FIRST/data/ShotExperiments`. Rows contain batch, attempt, target/measured RPM, battery voltage, motor power, motion, applied hood position/angle/range, encoder conversion, feed power, gate settings, and labels. Approximately 10 Hz idle / up to 50 Hz around feed/recovery, with state changes logged immediately. The bounded 6000-row log is held in RAM to avoid disk stalls during control and saved only after outputs stop. A crash/power loss loses this CSV; existing HardwareMonitor provides separate session data. At the row cap arming is inhibited; STOP/restart rather than run without a log.

After pulling a CSV, run `python3 tools/summarize_pollen_shots.py path/to/pollen-session.csv`. It groups batches, deduplicates repeated label rows, excludes INVALID/unlabeled attempts from fractions, and reports clean-entry fraction separately from retention after clean entry. Preserve the video for classification review.

## What a result means

- Higher clean-entry rate: improve consistency/trajectory before changing hardware.
- Higher clean-entry retention at lower speed: software trajectory choice may reduce rebound.
- Clean entries still unpredictably leave across repeatable tests: inspect impact location, backspin, ball variation, and cell motion before drawing a hardware conclusion.
- A single wheel plus stationary hood cannot independently set translation and spin. This test cannot promise to remove backspin. An undershooter tomorrow changes contact geometry; remeasure angle, RPM-to-ball-speed relation, spin, and feeder behavior before reusing any learned table.
